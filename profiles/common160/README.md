# Common160 firmware profile

This directory identifies the separate **160 MHz on all three CPUs** experiment added in release v1.2.0. [CURRENT_FIRMWARE.json](CURRENT_FIRMWARE.json) pins the measurement and separate diagnostic images, native build/source evidence and exact experiment configuration. All paths in that JSON are relative to the repository root. This manifest is preserved as the build/programming-time snapshot; subsequent PPK2 acceptance is recorded separately in the [completed common160 campaign](../../ROW_Data/common160/source_campaign.json).

The repository-root CURRENT_FIRMWARE.json continues to identify the maximum-clock campaign. No board is switched merely by updating this repository. Select `--clock-profile common160` for acquisition or serial validation; select `-DBENCH_CLOCK_PROFILE=common160` when compiling.

Native measurement and diagnostic builds passed on all three targets. The [Pico common160 diagnostic](../../hardware/common160/2026-09-11/rp2040_diagnostic_01.json) subsequently passed all twelve workloads with exact call counts and final DONE, reporting CPU 160 MHz, peripheral clock 48 MHz, internal VREG selection 12 (1.15 V) with regulation ready, and Flash divider 4 for 40 MHz QSPI. The [exact silent release UF2 was installed afterward](../../hardware/common160/2026-09-11/rp2040_measurement_programming_01.json); common160 is the Pico's latest recorded installation.

The [ESP32 common160 diagnostic](../../hardware/common160/2026-09-11/esp32_diagnostic_01.json) also passed all twelve workloads with exact call counts and final DONE, reporting CPU 160 MHz, APB 80 MHz, digital-bias selection 4 (SDK nominal 1.10 V), core 0 and an uninitialized radio. The [matching silent release bootloader, partition table and application were installed afterward](../../hardware/common160/2026-09-11/esp32_measurement_programming_01.json), with successful esptool hash verification of all three segments. Common160 is the ESP32's latest recorded installation.

The [STM32F446 common160 diagnostic](../../hardware/common160/2026-09-11/stm32f446_diagnostic_01.json) passed all twelve workloads with exact call counts and final DONE through USART3/PC10, reporting nominal CPU 160 MHz, APB1/APB2 40/80 MHz, Scale 1 ready with OverDrive disabled, five Flash wait states, full FPU access and TIM2 prescaler 7999. The [matching silent release BIN was installed afterward](../../hardware/common160/2026-09-11/stm32f446_measurement_programming_01.json) through ST-LINK mass storage, with completed host transfer and no `FAIL.TXT` after five seconds. Common160 is the STM32's latest recorded installation.

All three common160 functional diagnostics passed and their silent measurement images were installed. The earlier maximum-clock RP2040/STM32 PASS records remain unchanged, and the ten accepted ESP32 240 MHz captures retain their original v3 provenance without repeat acquisition. All three common160 PPK2 capture sets are now accepted: ten new independent cold boots per board, 30 captures with 153,391,616 samples and 360 complete workload windows, from source commit `f19c3b4c96e85d6348c9966bc012bbdbbeac1112`. Diagnostic execution and programming observations do not independently validate the silent images' complete execution or provide independent flash-readback attestations. The [completed selection](../../ROW_Data/common160/source_campaign.json) retains original metadata, profile/image pins and the separate fixture clarification; no earlier waveform or idle baseline is reused. The original image manifest and its historical preparation/pending fields are not rewritten to represent the later acceptance state.

Software verification includes 84 Python tests, 119 kernel-reference checks and twelve host runner simulations across the two profiles. Static native checks bind source, configuration and images; confirm fixed counts/input bytes, the selected 160 MHz configuration and absence of application serial reporting in measurement images. ARM maximum-clock regression BINs are byte-identical to the published v1.1.0 images.
